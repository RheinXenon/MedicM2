## 核心技术栈

### AI 模型
- **OpenAI GPT-4**: 医学诊断推理
- **GPT-4 Vision**: 医学影像分析
- **text-embedding-3**: 文本向量化

### RAG 技术
- **ChromaDB**: 向量数据库
- **LangChain**: RAG 框架
- **语义检索**: 专业知识匹配

### Agent 架构
- **多智能体协作**: 5个专科医生 + 1个会诊专家
- **独立诊断**: 每个 Agent 基于专业知识独立判断
- **协同决策**: 会诊 Agent 综合所有意见

## 核心流程

### 1. 初始化阶段
```python
system = MedicalDiagnosisSystem()
```
- 加载科室配置
- 初始化向量数据库
- 创建知识检索器
- 初始化 5 个专科医生 Agent
- 初始化会诊 Agent
- 初始化多模态处理器

### 2. 诊断流程
```python
result = system.diagnose(case_data)
```

**步骤1: 多模态输入处理**
- 解析文本病历
- 如有影像，使用 GPT-4 Vision 分析
- 生成结构化输入

**步骤2: 相关性判断**
- 每个医生 Agent 评估病例相关性
- 基于关键词匹配计算相关度分数
- 决定是否深入诊断

**步骤3: 知识检索 (RAG)**
- 根据症状生成查询
- 从向量库检索专业知识
- Top-K 相关文档 (默认5个)

**步骤4: 独立诊断**
- 每个相关科室独立诊断
- 结合病例信息 + 检索知识
- 生成专业诊断意见

**步骤5: 会诊汇总**
- 综合所有科室意见
- 分析主要病因
- 制定治疗方案
- 评估预后

**步骤6: 输出结果**
- 生成结构化报告
- 保存诊断结果

## 关键特性

### 1. 多智能体协作
- **独立性**: 每个Agent独立诊断，避免相互干扰
- **专业性**: 基于专业知识库，诊断更准确
- **协同性**: 会诊Agent综合所有意见

### 2. RAG 知识增强
- **动态检索**: 根据病例动态检索相关知识
- **上下文增强**: 为Agent提供专业背景知识
- **持久化存储**: ChromaDB向量数据库

### 3. 多模态输入
- **文本理解**: 解析病历文本
- **图像分析**: GPT-4 Vision分析医学影像
- **信息融合**: 综合多模态信息

### 4. 智能相关性判断
- **关键词匹配**: 基于专业关键词
- **相关度评分**: 量化相关程度
- **动态筛选**: 只有相关科室深度诊断

## 扩展性设计

### 添加新科室
1. 在 `config/departments.json` 添加配置
2. 创建知识库目录和文档
3. 系统自动创建对应 Agent

### 自定义知识库
1. 在科室目录添加 `.txt` 文件
2. 系统自动向量化和索引
3. 支持动态更新

### 修改诊断逻辑
1. 继承 `DoctorAgent` 类
2. 重写 `diagnose()` 方法
3. 自定义相关性判断逻辑

### 更换模型
1. 修改 `.env` 配置
2. 支持任何 OpenAI 兼容 API
3. 可切换不同模型

## 性能指标

### 响应时间
- **单病例诊断**: 约 30-60 秒
- **图像分析**: 每张图约 5-10 秒
- **知识检索**: 每次查询 < 1 秒

### 资源消耗
- **内存**: 约 500MB - 1GB
- **存储**: 向量库约 100MB (取决于知识库大小)
- **API 调用**: 每次诊断约 6-10 次 (取决于相关科室数)

### 成本估算 (GPT-4)
- **纯文本病例**: 约 $0.1 - $0.3
- **含图像分析**: 约 $0.2 - $0.5
- **批量诊断**: 使用 GPT-3.5 可降低成本

## 安全性和隐私

### 数据安全
- 本地向量数据库存储
- 不保存原始病例到云端
- API 调用使用加密连接

### 隐私保护
- 不应使用真实患者数据
- 测试数据应脱敏处理
- 符合数据保护规范

## 局限性

1. **依赖 API**: 需要稳定的网络和 API 服务
2. **成本**: GPT-4 调用成本较高
3. **准确性**: 受知识库质量和模型能力限制
4. **非临床工具**: 仅供学习研究，不能替代真实诊断
