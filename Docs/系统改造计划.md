# Agent Hospital 系统改造计划

## 1. 改造目标
- **科室内闭环演化**：让每个科室独立累计病例库与经验库，符合参考论文的训练范式。
- **分诊路径一致性**：确保护士推荐的科室始终与系统配置匹配，避免错配导致的 fallback。
- **业务覆盖扩充**：扩展可用科室以涵盖常见疾病谱，支撑分诊与训练规模化。

## 2. 关键痛点
1. 现有病例库/经验库在全院共享，医生无法针对本专业沉淀经验，演化信号被稀释。
2. 分诊提示词缺少硬性约束，LLM 会返回未配置的科室名称；系统只能强制切换至默认科室，导致体验与训练数据失真。
3. `departments.json` 仅包含 5 个科室，无法覆盖多数分诊建议，限制了后续扩容。

## 3. 改造方案
### 3.1 分科知识库隔离
1. 在 `AgentHospital` 启动阶段为每个科室创建独立的病例库与经验库存储前缀（例如 `case_base/{department_id}`）。
2. 调整 `EvolvingDoctorAgent` 依赖注入逻辑，使医生只读写所属科室的子库；同时保留公用接口，便于统计与可视化。
3. 为 `MedicalCaseBase` 与 `ExperienceBase` 增加轻量工厂/缓存层，避免重复加载磁盘数据。

### 3.2 科室配置扩充
1. 结合常见挂号分类与历史分诊结果，扩展 `departments.json` 至至少 15–20 个覆盖性科室（如耳鼻喉科、内分泌科、皮肤科、风湿免疫科等）。
2. 为每个科室补齐 `specialties` 与 `keywords`，确保分诊关键词匹配有足够分辨度。
3. 引入 `department_aliases` 字段，用于映射常见别称，方便分诊阶段做标准化。

### 3.3 分诊链路收敛
1. 更新 `NURSE_TRIAGE_TEMPLATE`，显式要求 LLM 只能从提供的科室列表中选择，并输出标准化英文 ID；若返回非法值，回退到本地关键词排序结果。
2. 在解析层增加合法性校验与 alias 映射，确保 `recommended_departments` 均存在于配置。
3. 为分诊模块增加日志/统计，监控越界率与关键词命中情况，为后续调优提供数据。

### 3.4 数据迁移与验证
1. 设计一次性迁移脚本，将历史共享病例/经验按 `department` 字段切分到对应子库。
2. 为新结构编写单元/集成测试，验证不同科室间不会互相读取数据，并覆盖分诊合法性检查。
3. 在批量仿真前执行烟囱测试，确认各科室最少存在 1 条病例与 1 条经验规则。

## 4. 里程碑 & 输出
| 里程碑 | 交付 | 验收标准 |
| --- | --- | --- |
| M1 | 分科存储框架 | 单科室回归通过，数据读写隔离 |
| M2 | 扩展科室配置 & 分诊模板 | 分诊越界率 < 5%，新增科室全部可挂号 |
| M3 | 迁移与测试 | 历史数据成功迁移，自动化测试全部通过 |
